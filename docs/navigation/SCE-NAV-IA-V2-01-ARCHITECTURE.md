# SCE Navigation / Information Architecture V2 — Phase 01 (Foundation)

Programme: **SCE-NAV-IA-V2-01**  
Status: **Audit + architecture foundation only** (no live navigation changes)  
Base commit: `38fd4efb78b206e0771e78a1fadcd4792d3b692a` (STAGE, post SCE Icon System V2 closure)

## Executive summary

The authenticated club workspace navigation is **technically complete and permission-aware**, with a single canonical owner (`lib/nav/nav-config.ts`) driving shell presentation via `app-navigation-domains.ts` and `app-navigation-model.ts`. Product direction consolidates **Organisation into Club**, elevates **Publishing** to L1, and keeps **Dashboard / Planung / Kommunikation** as responsibility domains.

Machine-readable target mapping: `docs/navigation/SCE-NAV-IA-V2-01-target-ia-matrix.json` (generated by audit tests).

## Active state contract

Central resolver: `resolveActiveAppNavigation(pathname, model)`.

Examples (target taxonomy):

- `/dashboard/org-units` → L1 **Club**, L2 **Organisation**, L3 org-units  
- `/dashboard/website/pages/123` → L1 **Publishing**, L2 **Inhalte**, local page context via page UI  
- `/dashboard/teams/123` → L1 **Club**, L2 **People & Teams**, `TeamCockpitNav` local  

Avoid new scattered pathname hacks; extend domain metadata in V2-02.

---

## Permission-aware navigation

Unchanged model: filtered sections → domains → rows. Parent visibility must not imply child visibility; sibling denial must not hide authorized routes. Empty domains hidden unless default destination is authorized.

---

## App Explorer

Single taxonomy via `model.domains`. V2 adds **publishing** domain section; **organisation** section disappears (items appear under **club** groups). Search index remains derived from domains/modules/children.

---

## Quick Access

Pins use `navigation.{navItemKey}`; icons from `getQuickAccessSceIconName`. IA move does not change canonical keys in V2-02 (routes stable).
